em_execute / em_batch_execute are the hot paths; keep them within ~1 ms of the raw spawn cost and keep server start-up module-light. Decisions taken on branch feature/permance_on_hotpaths (2026-10-14):

- Never query `chunks_vocab_instance` filtered by chunk id: fts5vocab cannot push the filter down and scans the whole index (≈450 ms per call at 60k chunks). "Searchable terms" are computed in JS from the document's own chunk bodies (`topTermsOf` in src/storage/terms.ts).
- Pure-JS dependencies (zod, MCP SDK, fast-glob, ignore) are bundled into dist (`noExternal`) and each entry is one file (`splitting: false`); only native/heavy modules (better-sqlite3, sqlite-vec, transformers, tree-sitter, tsx, turndown) stay external. Externalised deps cost ~500 module loads per boot. The shim exports NODE_COMPILE_CACHE so V8 bytecode is reused across launches.
- Server single file, static imports only (feature/adjudicator, swarm run 20261104-483f39, task #65, 2026-11-04; supersedes dab580d's splitting:true for server/cli). dist/server.js and dist/cli.js are one self-contained file each: `eminiar upgrade` reinstalls the stable copy IN PLACE, and a chunk a running server / `eminiar ui` / the upgrading CLI had not loaded yet vanished (ERR_MODULE_NOT_FOUND in em_reindex, em_swarm plan). Everything the server reaches (server.ts, tools/*, embeddings/provider.ts, adjudicator/* incl. adjudicator/cli.ts via doctor.ts) imports INTERNAL modules statically; dynamic import() only for external packages (@huggingface/transformers, web-tree-sitter) or runtime paths. Reason: without splitting esbuild wraps each dynamically imported internal module, and everything it imports, in a lazy __esm initialiser; once that reached zod while the MCP SDK loaded zod eagerly, the SDK's top-level z.custom() ran first ("Class2 is not a constructor"). The CLI keeps its per-command dynamic imports (zod wrapped there, only initialised by wrapped modules, SDK not bundled). scripts/check-bundle.mjs runs in `npm run build` after tsup and fails on: any sibling-file import in server.js/cli.js, any lazy wrapper other than init_esm_shims in server.js, zod wrapped while an unwrapped module inits it or the SDK is bundled unwrapped. Measured (25 interleaved spawns → initialize reply, M-series, compile cache): server base 6db2683 71 ms / split 84 ms / single-file static 73-74 ms (no cache 86 / 103 / 90). CLI `--version` 66 / 43 / 74 ms, `statusline` 67 / 50 / 74 ms (single file costs the CLI ~25-30 ms vs split, ~7 ms vs main's single file; accepted for upgrade safety). The hook build stays split (short-lived processes).
- Per-call caches: permission rules (stat-revalidated), compiled bash rule regexes, env allowlist patterns, interpreter detection, session id (mtime), prepared statements in SqliteAdapter (`prep()`). Stats are recorded on setImmediate so the reply is written first. Sandbox tools do not await the reindex-queue drain.
- Measure with `npm run bench` (scripts/bench-hotpath.mjs drives dist/server.js over stdio) before and after any change to these paths; run it alone, not concurrently with tests.
