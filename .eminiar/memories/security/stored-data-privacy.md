What eminiar keeps on disk, and how private it is (branch fix/privacy-basics, 2026-11-08).

1. Captured output is masked at one point: indexContent (src/index/indexer.ts) runs redactSecrets() over the title, content, string meta (the intent) and any pre-cut chunks of every document whose source is exec, batch or url (em_execute, em_execute_file, em_batch_execute, em_fetch_and_index). Anything that indexes command output, stderr included, must go through indexContent with one of those sources. Files, code, git, docs (em_docs pages are documentation, where example keys are the content), memories and session documents are not touched there. What the tools show inline (small outputs, the head/tail preview, batch inline output) is as printed; sections returned for an intent or queries, and "searchable terms", come from the masked copy.
2. The short error text of a failed tool call (classify.ts errorText: first 4 KB masked, then clipped to 400) and its command summary are masked before the error event is stored; persist() indexes that event as a session document for em_recall. Still stored as written: prompts, assistant replies, subagent reports, tool-call command heads in events and hook.log, the global fetch cache (docs sync parses specs from it), documents.uri of a url (the refetch key). Masking is best effort: an opaque token alone on a line or a password in prose has no shape or name to match.
3. redactSecrets() lives in src/adjudicator/redact.ts next to redact() and reuses its RULES (see adjudicator/redact-rules), so Ryan's branches that edit that file keep merging. The hooks-off test lists redact.ts as not probed: it is pure text rules. Differences from redact(), each from measuring real output: no email/hex/base64 run rules (git SHAs, checksums, lockfile integrity, authors); no clean() (stored output keeps every character); a lone `key` keeps a value that reads as a name, path or id (under 20 chars, no digit or no letter, a dot or space, a UUID, an `algo:hex` digest, or parts between `/ _ - :` that are all under 20 chars with a plain lowercase word among them, where a long hex part may follow a `:` as in `session:<hex>`) and masks an opaque one (`live_<token>`, `prod-<token>`, `6AE843FF/INV0001A2B3…`); about 0.9% of random 32-char base64url tokens and 0.3% of alphanumeric ones still pass, mostly through the no-digit rule; a private key block ends at END within 64 KB and before the next BEGIN, else the rest of the BEGIN line and the base64 lines under it (indented or behind + > -) go; extra bare token shapes (ya29., hvs./hvb./hvr., do[por]_v1_, shp*_, pypi-, the ECR password). redact() returns exactly what it did before.
4. Output stored before this change keeps its text: exec/batch/url documents until a purge of the index scope (masking them in place is the follow-up PR), session error documents until a sessions purge.
5. Modes (POSIX): ensureDirs() creates the home 0700. An existing home is tightened (stat first, chmod only if looser than 0700, once per process) only when it is the default ~/.eminiar or holds global.db or install.json and nothing that is not eminiar's (an empty folder does not count), because EMINIAR_HOME can come from a repo's settings and be relative ("." is the project). restrictDbFiles() makes db, -wal and -shm 0600 right after every SqliteAdapter and GlobalDb open; SQLite gives the sidecars the main file's mode. Project files are never chmodded.
6. em_purge sessions also deletes the source "session" documents, which em_recall and the prompt hook recall. Exec/batch outputs carry a session_id but belong to the index scope.

Measured on M-series (this repo, 2026-11-08): redactSecrets ~30 ms/MB (44 µs for 5 KB, ~60 ms at the 2 MB cap). Lines it changes: 0/180 git log --format, 0/549 npm ls, 0/595 find, 1/6016 package-lock.json, 74/69321 src (identifiers ending in Key/pass/token followed by a type or value, and redact.ts's own comment examples), 530/222857 git log -p (mostly the redact tests' fake secrets). Hooks load redact.ts with the adjudicator off: +0.4–0.75 ms p50 on success (module load), +1.7–1.9 ms on a failed tool call's PostToolUse (first redactSecrets call), against hook budgets of seconds. Retention and size caps are a separate item.
