Adjudicator brief units grammar, closed lists and check labels (swarm run 20261105-1d96f4, task #169, review1 F1-F4, branch feature/adjudicator, 2026-11-05). In src/adjudicator/units.ts: (1) ROUTINE_OBJECT's subjects ("what the linter reports", "any failures the e2e suite reports") come from ONE closed list ROUTINE_SUBJECT (it/they/you/the linter|compiler|checker|tool|runner|build|ci|tsc|eslint|[e2e|unit|integration|full|test] tests/specs/suites), used in both the what(ever) branch and the trailing relative clause. Never let `the \w+` back in, because "fix whatever the scanner reports" is real work. Problems that turn up on their own use the closed EMERGE list (show/come/turn/pop up, appear, remain, is/are left|broken|failing). (2) After a CHECK_LABEL ("Verification:", "Done when"), the rest must be CHECKS_ONLY AND routine: either it contains a TOOL_CHECK command (KNOWN_CHECK: npm/npx/tsc/typecheck/lint/vitest…, or ci), or every word is generic (the tests/build/suite + pass/green). So "Definition of done: the migration tests and the rollback specs" and "Done when the new retry tests pass" stay as work. (3) The colon form of PROTOCOL[2] ("Verify: …") only matches a check named by its tool (TOOL_CHECK), never generic tests, so "Verify: the tests cover the retry path" stays. When in doubt, keep the statement.
UPDATE (task #187, review2 R2-1..R2-3, 2026-11-05), supersedes (2) and (3): KNOWN_CHECK/routineChecks are gone. After ANY CHECK_LABEL (colon labels incl. "Verify:"/"Check:"/"Confirm:", and "done when") the rest must match ROUTINE_CHECKS, a check list where EVERY item is a ROUTINE_ITEM: (the|all|full|whole|entire)* + a whole TOOL_CHECK command or a generic noun (tests/specs/suite/build/ci), then flags/paths, or "in|under <path>". One command never clears other items ("the migration tests, the rollback specs and typecheck pass" stays) and a tool word used as a description is not a command ("the typechecker regression tests", "the ci-workflow tests"). A named suite is work too, so "Done when typecheck, lint and the adjudicator tests are green" and "Verify: typecheck, lint, the docs + adjudicator-hooks tests." are now KEPT (forced choice: keep). The colon alternative of PROTOCOL[2] was removed and label-led clauses never reach PROTOCOL, so "Verify: npm test covers the new retry path" / "Verify: npm run db:migrate succeeds on a fresh database" stay. Unlabeled, CHECKS_ONLY keeps HEAD's predicates; "is/are green" only counts for routine items (ROUTINE_GREEN), so "The migration tests and the rollback specs are green." stays. A label drop does not carry CONTINUATION ("Done when the tests pass; the cache must survive a restart" keeps the cache). ROUTINE_OBJECT closed-list additions: bare tool subjects (tsc|eslint|biome|vitest|jest|lint|ci), "(that|which) [SUBJECT] VERB", raises/throws, and EMERGE (are/get reported|flagged, now/still fail, start failing, come back, you see|find|hit, needs fixing, goes red, doesn't pass). Corpus drop-diff vs pre-#187: 0 newly dropped, 9 routine "Verify: …" lists newly kept, 0 verdict changes. UNITS_VERSION stays "4" (HEAD is "3"). Verified with a drop-list diff over 1782 real briefs: no change against the pre-#169 tree, and against HEAD only design3's 4 bare headings are newly dropped.
