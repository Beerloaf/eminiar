Adjudicator MCP surface (branch feature/adjudicator, swarm run 20261104-483f39, task T9, 2026-11-04): ToolDef has an optional `available(config)`; src/server.ts lists only availableTools(tools, startConfig), so em_adjudicate (score/explain/stats/feedback) is absent while adjudicator.enabled is false and needs /mcp reconnect after enabling. The server registers the embedding provider via registerServerProviders(config) (static imports since #65: nothing the server reaches may dynamic-import an internal module; scripts/check-bundle.mjs enforces it; registration only when embedding is the effective provider with context "server"). em_swarm plan does ONE batched adjudicate() call per plan (src/adjudicator/swarm.ts adjudicatePlan, budget timeouts.planMs, heuristic on any failure); the advice step in em_swarm.ts is wrapped in try/catch and on error returns the planned tasks plus "Adjudicator advice unavailable for this plan (the tasks are planned)" (#66). It stores a `plan` row per task (runId, taskId, action "advised") and appends one line per task "#N → <agentType> · model X · effort Y (complexity N, conf 0.NN)" — the coordinator passes BOTH `model` and `effort` on the Agent call (per-call effort needs Claude Code 2.1.292+; levels low..max, max only at complexity ≥ 3.75). Pinned agents (resolveAgentPin, apply.respectFrontmatter) get "pinned opus (adjudicator would pick haiku; remove the pin …)" instead of a model to pass, unknown pins are not overridden, and such rows carry pinDeferred and earn no savings credit (see adjudicator/advise-respects-pins-and-agent-effort). "role suggested: R (planned: P)" is added when they differ. The planned role adds +1 to its own score, so a role-differs note needs strong evidence. Under CLAUDE_CODE_SUBAGENT_MODEL_FORCE the block says the model is informational. Everything is a no-op (no import, no rows, no output change) when the adjudicator or surfaces.plan is off. The feedback `note` is stored redacted (≤ 500 chars) and shown by explain (#26).
