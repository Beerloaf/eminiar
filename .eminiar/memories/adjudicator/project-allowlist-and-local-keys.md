Adjudicator project-layer allowlist and local-key rule (task #32, swarm run 20261104-483f39, 2026-11-04, branch feature/adjudicator; implements constraint adjudicator/project-layer-trust-boundary rules 1 and 3). src/config.ts: PROJECT_ADJUDICATOR_KEYS = enabled, mode, surfaces, promptMode, minPromptChars, tiers, weights, apply, advice, embedding, learning, cache. projectLayer() keeps only those from <root>/eminiar.config.json; provider, typesafe, openai (preset/baseUrl/model/price — price matters because a 0 price bypasses budget.dailyUsd), keyEnv, remoteConsent, privacy, budget, timeouts, breaker come only from ~/.eminiar/config.json + EMINIAR_* env. Exception: a project section containing a key-like field is passed whole so the secret check still rejects the config (defaults, adjudicator off). Exports droppedProjectAdjudicatorKeys(raw) and projectAdjudicatorWarning(root) (one line, for doctor/status; wiring into src/adjudicator/cli.ts was left as a follow-up task because #35 owned cli.ts). Keys: resolveKey(id,{fileOnly}) skips every env var; src/adjudicator/config.ts keyFor(r, env) passes fileOnly = !r.configuredRemote and is the ONLY way providers (openai.ts, typesafe.ts) and currentKeyFingerprint get a key, so a loopback target gets only a key-file entry for its own id, never keyEnv / provider env / EMINIAR_ADJUDICATOR_KEY. Tests that configure the provider must write the adjudicator section to $EMINIAR_HOME/config.json, not the project file (tests/unit/adjudicator-hooks.test.ts configure() does). Regression tests: tests/unit/adjudicator-config.test.ts "project layer trust boundary (#32)" and tests/unit/adjudicator-providers.test.ts "no env key for a loopback provider (#32)".
