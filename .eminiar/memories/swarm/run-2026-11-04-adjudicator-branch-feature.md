Swarm run 20261104-483f39 (swarm "feature", hierarchical, 2026-11-04): done.
Goal: Adjudicator (branch feature/adjudicator): an OPTIONAL, off-by-default subsystem that uses a tiny fast model to score request complexity and pick the right eminiar tool, Claude model size and swarm agent role per piece of work, so eminiar speeds up development while cutting token usage.
1) Providers (pluggable, optional): jev from https://typesafe.ai/ (tiny fast structured-output model; API key in a local 0600 file under ~/.eminiar, never in repo/index/logs/memories/dashboard), other small structured models via OpenAI-compatible endpoints, local runtimes (Ollama, LM Studio/llama.cpp, in-process @huggingface/transformers which eminiar ships), plus a zero-model heuristic fallback. Investigate local-model routing feasibility and latency.
2) Scoring: complexity score per request/task; scores per candidate eminiar tool (em_execute, em_batch_execute, em_search, em_symbols, em_graph_impact, em_docs, em_recall…), per model tier (haiku/sonnet/opus/fable + effort) and per swarm role; explainable reasons, deterministic fallback, tunable weights, cheap learning from outcomes.
3) Integration: hook path (UserPromptSubmit / PreToolUse advice) with a hard latency budget, fail-open; em_swarm plan/spawn suggests role, model and effort per task; a tool/action to ask the adjudicator directly.
4) Onboarding asks whether to enable the adjudicator for tool, model and agent selection and which provider; CLI `eminiar adjudicator …` to configure/test; doctor checks.
5) Every decision recorded (input summary, scores, choice, provider, latency, token/cost estimate, outcome) in local SQLite; new dashboard tab with stats, call log, decision detail, provider health, estimated savings.
6) docs/adjudicator.md + configuration/cli/dashboard docs, schema regenerated, minor version bump, extensive tests with stubbed providers, adversarial review rounds until clean.
Outcome: Shipped the adjudicator on feature/adjudicator (v0.13.0): an opt-in, off-by-default subsystem that scores request complexity and suggests the eminiar tool, Claude model tier, effort and swarm role, for prompts, Agent dispatches and em_swarm plan.
Built: providers (heuristic default, embedding k-NN, Jev/typesafe, OpenAI-compatible incl. local Ollama/LM Studio/llama.cpp), engine with cache, breaker, slow guard, daily $/call caps and auth lockout; v8 storage; outcome learning and net savings; hooks (advice + opt-in apply); em_adjudicate; em_swarm plan advice; CLI `eminiar adjudicator` and the install/onboard question; doctor checks; dashboard Adjudicator tab; docs; 0.13.0.
Verified: typecheck, lint, build (+ check-bundle), build:ui, 1417 tests passing (64 files), 28+ integration tests on built artifacts, hook bench within 1 ms of main when off, adjudicator-off hook output byte-identical to main.
Five adversarial review rounds found and fixed ~45 issues, incl. two critical (project config redirecting keys/prompts; __proto__ pollution), a server start-up crash from esbuild lazy wrappers (now guarded at build time), breaker races, consent bound to origins and to a repo-proof trust anchor, and redaction gaps.
Open: accepted limits in docs/adjudicator.md (absolute sibling EMINIAR_HOME in non-git archives; keys split across lines); Jev accuracy unmeasured until a key is added; pre-existing project-config issues recorded in security/project-config-layer-followups.
